# 정책 비상등 — Policy Watch

**기존 정책 팩트체크 앱과 별개인 새 Streamlit 프로젝트**입니다. 기존 저장소에 덮어쓰지 말고 새로운 GitHub 저장소와 새로운 Streamlit 앱을 만드세요.

정책 PDF를 기준으로 국내 공개 기사·블로그·SNS 게시물의 사실 주장을 대조합니다. 정책문서가 직접 반박하는 주장이 있으면 **🔴 거짓 정보 포함** 비상등을 표시하고 게시물 구절과 정책 PDF 구절·페이지를 함께 보여 줍니다.

## 사용 흐름

1. 사이드바에 OpenAI API 키를 입력합니다.
2. 정책 공고·법령·지침·공식 설명서 PDF를 올립니다. 정책 본문과 개정·추가 문서를 함께 올릴 수 있습니다.
3. **정책명**과 **정책 기준일**을 입력합니다. 기준일은 적용 내용을 비교할 날짜이며 게시물 검색 시작일이 아닙니다. 발표일·시행일이 다르면 비교하려는 기준일을 선택하세요.
4. 기사·블로그·SNS 수집 유형과 최대 링크 개수를 선택합니다.
5. **정책문서 확인 후 공개 자료 수집**을 누릅니다. 문서가 정책문서인지, 입력한 정책과 같은지, 기준일과 부합하는지를 먼저 확인합니다.
6. 제목·유형·발행일·본문 상태·원문 링크가 있는 목록을 확인합니다. 펼침 영역에서 확보한 본문을 읽을 수 있습니다.
7. 판정할 자료를 선택하고 **선택한 자료 일괄 판정**을 누릅니다.
8. 자료별 비상등과 개별 주장, 게시물 원문 구절, 정책 PDF 구절·페이지, 설명·정정 내용을 확인합니다.
9. 목록 CSV 또는 근거 포함 JSON 보고서를 내려받습니다.

자료 입력을 바꾸면 기존 수집·판정은 초기화됩니다. 현재 세션에서만 유지되므로 결과가 필요하면 내려받으세요. 판정 완료 자료는 재사용하며 분석 오류 자료는 같은 버튼으로 재시도할 수 있습니다.

## 판정 기준

| 표시 | 의미 |
| --- | --- |
| 🔴 거짓 정보 포함 | 사실로 제시한 주장 중 하나 이상을 정책문서가 직접 반박하며, 적용 시점·대상·정책 버전의 비교가 타당함 |
| 🟡 불확실 | 정책문서만으로 참·거짓을 확정할 수 없는 검토 대상 주장이 있음 |
| 🟢 검토한 주장 일치 | 검토한 사실 주장들이 정책문서의 직접 근거와 일치함 |
| 판정 대상 없음 | 사실 주장이 아닌 의견·질문 등이거나 검토 가능한 사실 주장 없음 |
| 대상 제외 | 다른 정책, 국내 맥락 미확인, 요청한 게시물 유형에 해당하지 않는 자료 등 |
| 본문 미확보 | 로그인·동적 페이지·접근 오류 등으로 본문을 읽지 못함 |
| 분석 오류 | API 또는 모델 응답 처리 실패. 사실 판정이 아님 |

균형 기준으로 판정하며 별도의 엄격/균형 선택은 없습니다. 게시물에 **문서에 없는 내용**이 있다는 이유만으로 거짓이라 하지 않습니다. 정책이 다른 시점에 개정되었거나 대상이 다른 경우에도 단순한 차이를 거짓이라고 단정하지 않습니다. 인용한 허위 주장을 반박하는 글, 단순 질문, 의견은 글쓴이의 거짓 주장으로 취급하지 않습니다.

비상등은 **업로드한 문서와 특정 주장 간 모순에 대한 LLM 판단**입니다. 작성자의 고의나 의도를 판단하지 않습니다. 녹색은 게시물 전체의 정확성을 인증하지 않습니다. 게시물당 최대 12개 핵심 사실 주장을 검토하고, 모든 주장이 빠짐없이 추출됐다는 보장은 없습니다. 신뢰도는 LLM 자기평가이며 통계적으로 검증된 정답 확률이 아닙니다.

## 수집 범위와 한계

- OpenAI Responses API의 `web_search`를 실제 호출합니다. 유형마다 정책명·기준일 및 대상·금액·신청·예외 중심으로 2회 요청합니다. 세 유형 모두 선택하면 6회 검색 API 요청이며 API가 반환한 도구 호출 횟수도 표시합니다.
- 기본 최대 20개, 설정 가능 범위 5~50개입니다. 유형별 후보를 번갈아 담고 추적 파라미터·중복 URL을 정리합니다. 같은 호스트는 최대 10개입니다. 이는 전수 수집이나 전체 인터넷 조사 기능이 아닙니다.
- 기사 검색은 도메인 제한 없이 국내 한국어 언론·뉴스 포털을 요청합니다. 블로그는 Naver Blog·Tistory·Brunch·Velog, SNS는 X/Twitter·Threads·Instagram·Facebook의 공개 검색 결과를 대상으로 합니다. 지원 도메인은 `collector.py`에서 변경할 수 있습니다.
- 검색 도구의 출처·인용 메타데이터에 실제로 있는 링크만 사용합니다. LLM이 답변 텍스트 안에 생성한 임의 URL은 사용하지 않습니다. 정부 정책 원문 사이트는 감시 대상 게시물에서 제외합니다.
- 한국어 본문 여부를 우선 확인하고 국내 맥락·정책 관련성·유형은 LLM이 재검토합니다. 한국어라는 이유만으로 국내 작성자의 글임을 인증하지 않습니다.
- 블로그·SNS 로그인, 검색 색인 누락, 동적 렌더링, 사이트 접근 제한 때문에 일부 글은 제목·링크만 남을 수 있습니다. 접근 제한을 우회하거나 계정에 로그인하지 않습니다. SNS 전체 수집에는 각 플랫폼의 별도 API·권한이 필요할 수 있습니다.
- HTML 본문은 Trafilatura로 추출하며 댓글은 제외합니다. 최대 2MB 페이지를 받아 앞부분 18,000자까지 판정합니다. 잘린 글은 표시합니다. 추출한 표·문단의 문맥은 원문에서 재확인하세요.
- 발행일은 페이지 메타데이터이며 실제 게시일과 다를 수 있습니다. 자료 수집 시각은 별도로 기록합니다.
- 본문 확보 실패 자료는 목록에 남기고 판정 대상에서 제외합니다. 동일 본문 중복은 별도 표시합니다.

## 정책 PDF

- 최대 5개, 파일당 10MB, 합계 100쪽·추출 본문 15만 자입니다.
- 텍스트 PDF를 지원합니다. 스캔본은 OCR 처리 후 올려야 합니다. OCR·표·다단 문서 읽기 순서의 오류를 자동 보정하지 않습니다.
- 정책문서인지와 정책명이 맞는지는 업로드 내용으로 판단합니다. 정부 원본과의 동일성, 전자서명, 문서 진위·최신성을 인증하지 않습니다.
- 명백히 정책문서가 아니거나 다른 정책이거나 기준일과 불일치하면 수집을 시작하지 않습니다. 날짜가 확인 불가인 경우 경고 후 개별 주장 대조 시 적용 범위를 검토합니다.
- 추출하지 못한 페이지는 표시하고 판정 모델에도 전달합니다. 문서 충돌이나 누락이 결론에 영향을 주면 불확실로 판단하도록 지시합니다.
- 게시물과 정책문서를 각각 고유 구절 ID로 나누고 구조화 출력에서 실제 ID만 선택하도록 제한합니다. 인용문·문서 페이지·원문 링크는 앱이 실제 수집 자료에서 연결합니다. 구절이 원문에 있다는 것이 LLM의 의미 해석까지 정확하다는 뜻은 아닙니다.

## GitHub와 Streamlit Community Cloud 배포

1. **새 GitHub 저장소**를 만듭니다. 예: `policy-monitor`.
2. 압축을 풀고 `policy-monitor` 폴더 **안의 모든 파일**을 저장소 루트에 올립니다. `app.py`, `engine.py`, `collector.py`, `network.py`, `passages.py`, `pdf_support.py`, `reporting.py`, `requirements.txt`, `.streamlit/`, `.gitignore`, `tests/`, `README.md`가 포함됩니다.
3. https://share.streamlit.io 에서 새로운 앱을 만들고 저장소·브랜치·진입 파일 `app.py`를 선택합니다. Python 3.12를 사용하세요.
4. 선택 설정으로 Secrets에 다음을 넣을 수 있습니다. API 키는 앱 화면에서 입력하므로 Secrets에 넣지 않습니다.

```toml
OPENAI_MODEL = "gpt-4.1"
APP_PASSWORD = "원하는_경우_공유용_비밀번호"
```

5. 배포 후 새 앱 주소를 열고 API 키와 문서를 넣습니다.

Streamlit 앱은 GitHub Pages에서 실행되지 않습니다. 기존 앱을 교체하지 말고 새로운 Streamlit 앱으로 배포하세요.

## 로컬 실행

Python 3.12 환경에서:

```bash
python -m venv .venv
```

macOS/Linux는 `source .venv/bin/activate`, Windows PowerShell은 `.venv\Scripts\Activate.ps1`로 활성화합니다.

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 비용과 데이터 처리

OpenAI API 이용료가 발생합니다. 정책 확인 1회 + 선택한 유형별 검색 2회 + 판정할 게시물마다 비교 1회가 기본 구조입니다. 긴 정책문서는 매 비교 입력에 포함되므로 자료 수와 문서 길이에 따라 비용·시간이 늘어납니다. 처음에는 소수 자료로 확인하세요.

API 키는 세션 메모리에서 사용하고 파일이나 보고서에 저장하지 않습니다. 정책문서의 추출 텍스트와 수집한 글은 OpenAI로 전송됩니다. API 요청은 `store=False`이며, 이는 제공자의 모든 운영 로그가 사라진다는 뜻은 아닙니다. 앱은 PDF·게시물을 디스크나 DB에 자동 저장하지 않습니다. JSON 보고서는 선택한 근거 구절을 포함하고 전체 웹 본문은 제외합니다. 공개 접근 URL만 처리하며 사설·로컬 IP 및 내부망 리디렉션은 차단합니다.

## 검증 상태

```bash
python -m unittest discover -s tests -v
```

자동 테스트 21개가 통과했습니다. 직접 반박과 근거 없는 경우의 비상등 차이, 잘못된 구절 ID 차단, 시점 불일치, 반박 기사 속 인용문 처리, 검색 출처 null 처리, 중복 URL, 사설망 차단, 실제 PDF·한국어 HTML 추출을 확인했습니다. Streamlit 초기 화면과 모의 데이터의 수집 목록 → 선택 → 일괄 판정 → 비상등·문서 페이지 표시도 확인했습니다.

**실제 사용자 API 키로 유료 검색·판정하거나 외부 배포하지는 않았습니다.** 실제 수집률·판정 정확도는 운영할 정책문서와 대표 게시물을 이용해 검증해야 합니다. 자동 판정은 사람이 원문과 문서를 검토할 때 참고하는 결과입니다.
